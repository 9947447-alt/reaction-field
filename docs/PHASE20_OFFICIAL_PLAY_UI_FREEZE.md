## 1. 目的与 Beta 1 成功标准 `[FROZEN]`

Phase 20 把公开试玩从「Debug Alpha 模拟器」升级为「可交付给玩家的横屏卡牌客户端」。产品对标为类似欢乐麻将 / JJ 斗地主那种横屏沉浸牌桌体验，而不是调试双栏。

**没有成品视觉（插画 / 卡背 / 卡框 / 角色标 / 桌面材质 / 大厅 banner）就不是 Beta 1，仍是内部试玩。** CSS 卡框只能支撑内部迭代，不能当作发布标准。

Beta 1 必须同时满足：

1. 存在三条职责互斥、可独立测试的路径：`/` = 大厅（新人机 / 双人 / 教学入口，新 banner）。`/play` = 备战 + 桌子。`/debug` = 调试实验室。正式路径零调试暴露。
2. 正式桌是可交付的横屏卡牌桌：插画齐、手牌按「点选 + 出牌」操作、当前交互收敛为 1～3 个大按钮。
3. 默认开局是 **人机**；「本地双人」是显式选项。
4. 人机使用 **人类私密视角**；双人同屏仍公开双方手牌。已打出 / 响应 / 状态处理 / DIY 结果的牌是公开信息。
5. **正式主视口 = 横屏牌桌。竖屏正式流 = 「请横持」，不提供竖版对局。**（彻底废除 390 竖屏单列对局旧合同）
6. 首局教学是 **交互式脚本局**，不是 Debug Alpha 的折叠说明。
7. 规则版本仍为 `MVP0-P10`。

## 2. 可见性合同 `[FROZEN]`

### 2.1 产品决策

| 模式 | 人类玩家可见 | 禁止 |
| :--- | :--- | :--- |
| **人机（Solo vs NATBA）** | 自身手牌正面；对手手牌 **背面 + 张数**；双方角色 / HP / 状态 / 技能使用记号 / 场面基准 / 弃牌堆 / 牌堆余张 / 正式日志 / **已公开的最近行动牌面** | 对手**未打出**手牌 `definitionId` 与实例内容；牌堆未来顺序 |
| **本地双人** | 双方手牌正面同屏可见 | 不在 Phase 20 做两台设备 / 座位遮挡私密 |

NATBA Policy 继续只能消费 `AIObservation`。人机模式下，**正式 UI 也不得**把对手私有未打出手牌渲染给人类。

### 2.2 泄露边界

人机正式路径禁止从以下渠道露出对手**当前未打出**手牌内容或牌堆顺序：

- 手牌区、选中态、DIY 候选、普通出牌 / 响应 / 状态处理列表
- 卡牌 debug 行、折叠 JSON、Log ID、`rulesText` 原始块（正式页不得出现）
- 配置页预览、教学若演示对手私有手牌

正式日志与「最近行动」可公开展示已发生的出牌 / 响应 / 状态 / DIY 结果。测试不得只断言 DOM 无 `definitionId`；必须断言看不到对手私有牌的本地化名称、规则文本与操作按钮。

### 2.3 视图投影

- Engine 仍持有完整 `GameState`。
- 人机正式 UI 必须经 **Human Play View** 投影后再渲染。
- 双人模式可继续使用公开视图。
- `VisibilityMode = "public-debug"` 仅属于调试实验室。

## 4. 正式大厅、牌桌与调试实验室 `[FROZEN]`

必须拆分三条职责互斥、可独立测试的路由入口，禁止再把调试控件摸进正式流：

- **`/` = 大厅（新人机 / 双人 / 教学入口，新 banner）。**
  - 正式产品默认入口，仅负责展示品牌形象、新大厅视觉 banner、模式导航入口（单人人机对战 / 本地双人对战 / 交互式教学）以及关于与规则说明链接。
  - 大厅不渲染牌桌对局，不挂载 engine reducer。
  - 新大厅图由用户出，仓库只接入。
  - 竖屏访问大厅时，给出横屏沉浸体验或统一视觉引导。
- **`/play` = 备战 + 桌子。**
  - 正式主对局视口：承载战前阵容/模式确认与横屏牌桌、对局结算与交互式教学脚本局。
  - 正式主视口 = 横屏牌桌。竖屏正式流 = 「请横持」，不提供竖版对局。
  - 零调试暴露：禁止出现 Log ID、JSON、夹具标记、每座位控制方、未折叠的调试属性表。
- **`/debug` 本阶段零改动：夹具、Log ID、JSON、每座位控制方、公开双手都留着。**
  - 调试实验室整页不改：保留既有开发与测试夹具、Log ID、状态折叠 JSON、每座位控制方切换、公开双手全知视角、旧 Debug Alpha 面板。
  - `/debug` 无横屏强制限制，保持对桌面与移动端开发测试的最大兼容。
- **生产隔离检查**：正式入口产物无 fixture / private marker。
- **测试边界**：Fixture E2E 走 `/debug`；production E2E 走 `/` 与 `/play`。三者路由与职责在工程与测试上严格互斥。

## 5. 布局与可玩表面 `[FROZEN]`

正式产品全面改写为「横屏卡牌客户端」，产品对标：欢乐麻将 / JJ 斗地主那种横屏桌子，不是调试双栏。

### 5.1 视口与屏幕方向合同

- **正式主视口 = 横屏牌桌。竖屏正式流 = 「请横持」，不提供竖版对局。**
- 当用户在竖屏视口（如移动端竖屏）下访问 `/play` 时，呈现全屏横持提示遮罩（如「请横持设备以获得最佳牌桌体验」），阻断牌桌交互，不提供竖版对局。
- 彻底废除「390 竖屏单列完整对局」与「横屏双栏调试布局」旧合同。

### 5.2 横屏牌桌布局合同（`/play`）

**正式桌只保留：对手牌背横排、场面公开牌、己方横排点选、当前 1～3 个大按钮。禁止正式页复用调试 section / dl / details。**

牌桌由上至下标准布局：
1. **上方对手区**：对手角色身份、HP、状态徽章；人机对手手牌为 **背面横排 + 牌数指示**（双人模式为正面横排手牌）。
2. **中央牌桌与公共场面**：场面公开牌（已打出的公开牌面、最近行动公开牌、公开反应生成物、环境基准与弃牌堆计数）。
3. **下方己方区**：己方角色身份、HP、状态徽章；己方手牌 **正面横排点选**（支持点击升起选中、再次点击降下取消）。
4. **主交互操作区**：根据当前阶段（备课 / 主行动 / 响应 / 状态处理 / DIY）收敛为 **当前 1～3 个大按钮**（如「出牌」「响应」「跳过」「合成」等），视觉突出、易于触控。
5. **正式日志与信息展示**：不占用主牌桌可视面积，采用微缩抽屉或折叠浮层展示正式日志（无调试 JSON、无 Log ID）。

### 5.3 交互语义

- 己方手牌 **横排点选**，再点当前大按钮执行「出牌 / 响应 / 处理 / DIY」。
- 人机对手手牌 **背面横排 + 张数**。
- 不要求斗地主式复杂飞牌物理动画；要求的是横屏牌桌空间布局与点选语义，严禁在正式页复用调试表格、dl 列表或原始 details 展开器。

## 7. 交互式首局教学 `[FROZEN]`

本节覆盖 `docs/PHASE13_NEW_PLAYER_GUIDANCE_FREEZE.md` 与 `docs/PHASE15_FIRST_GAME_CONVERSION_FREEZE.md` 中「引导纯展示、不 dispatch」的 Beta 1 口径。Phase 13/15 仍是历史 Debug Alpha 引导的历史冻结。

- 旧 Debug Alpha 折叠说明不得当作 Beta 1 教学。
- Beta 1 教学是 **受控脚本对局**：玩家按步骤点当前高亮的合法操作。
- 引导可以 `dispatch` 既有 `GameAction`，**必须** 经 `engineReducer` 结算。禁止教学层直接改 HP、手牌、牌堆或胜负。
- 默认脚本：人机、老师 vs CEO、私密视角。步骤至少覆盖：看手牌 → 点选出牌 → 看到 AI 公开打出的牌 → 响应或过。
- 可跳过；跳过后进入普通正式对局。刷新重置。
- 人机教学不得展示对手私有未打出手牌。
- 不复制规则裁定。合法性仍由 Engine 裁决。
